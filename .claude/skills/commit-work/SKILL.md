# commit-work — ステージ＋コミット

`commit-staged` と同じ手順に、**先に `git add` する**ステップを足したもの。
メッセージの作り方・規約・禁止事項は `commit-staged` と共通なので、
**`commit-staged` スキルの「メッセージ規約」「注意」を読んでから**進める
（規約の実体はそちらにあり、ここには複製しない）。

## この skill 固有の手順

1. **ステージ前に作業ツリー全体を確認する**

   ```sh
   git status --short   # ステージ済み / 未ステージ / 未追跡をすべて把握
   ```

   - 変更が何も無ければコミットせず、その旨を伝えて止まる。
   - **無関係な変更が混在していたら勝手に全部まとめない**。指摘して分割コミットを提案し、
     何をステージするか確認する。

2. **ステージする**

   ```sh
   git add -A                # 原則は全変更。混在時は git add <path>... で対象を絞る
   git status --short        # ステージ結果を最終確認
   ```

   - **生成物・秘密情報・巨大ファイルが紛れていないか、`git add` 後に必ず目視で確認する**
     （`.gitignore` 漏れはここでしか気付けない）。ファイル名が無害でも疑わしければ中身を確認する。

3. あとは `commit-staged` と同じ。`git diff --cached` を根拠にメッセージを組み立て、

   ```sh
   git commit -m "<メッセージ本文>" -m "Co-Authored-By: <実行中のモデル名> <noreply@anthropic.com>"
   ```

   でコミットし、`git log --oneline -1` を提示する。**Co-Authored-By 行は必須**で、
   モデル名は固定せず、そのコミットを実行しているモデルの名前を書く。

## 注意

- `--amend` / `push` / ブランチ操作は行わない（依頼された場合のみ別途対応）。
- メインブランチ（`main`）上で直接コミットしようとしている場合は、その旨を伝えて確認する。
